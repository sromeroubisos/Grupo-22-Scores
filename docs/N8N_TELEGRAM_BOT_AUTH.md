# N8N Telegram Bot Authorization

## Resumen

El error:

```text
Could not find the table 'public.admin_telegram_users' in the schema cache
```

aparece porque el flujo de n8n intenta consultar `public.admin_telegram_users`, pero la tabla no existia en Supabase/Postgres.

Se agrego la migracion:

```text
supabase/migrations/20260424180000_admin_telegram_users.sql
```

La migracion crea:

- `public.admin_telegram_users`
- `public.normalize_telegram_phone_number(phone text)`
- `public.is_admin_telegram_user_authorized(p_telegram_user_id bigint, p_telegram_phone_number text)`
- `public.link_admin_telegram_user_identity(...)`

## Tabla

```sql
create table if not exists public.admin_telegram_users (
  id bigint generated by default as identity primary key,
  telegram_user_id bigint unique,
  telegram_phone_number text not null unique,
  username text,
  first_name text,
  last_name text,
  is_active boolean not null default true,
  created_at timestamptz default now()
);
```

Tambien se agrega un indice unico por telefono normalizado, para evitar duplicados como `+54 9 11...` y `54911...`.

## Cargar usuarios autorizados

Ejemplo:

```sql
insert into public.admin_telegram_users (
  telegram_phone_number,
  username,
  first_name,
  last_name,
  is_active
) values (
  '+5491112345678',
  'usuario_admin',
  'Nombre',
  'Apellido',
  true
)
on conflict (telegram_phone_number) do update
set
  username = excluded.username,
  first_name = excluded.first_name,
  last_name = excluded.last_name,
  is_active = true;
```

## Importante sobre Telegram

Telegram no entrega el numero de telefono en cada mensaje normal. Para autorizar por telefono, el bot debe pedirle al usuario que comparta su contacto.

El flujo debe validar que el contacto compartido sea del mismo usuario:

```text
message.contact.user_id == message.from.id
```

Si no se valida eso, una persona podria reenviar o cargar otro contacto.

## Nodo previo recomendado: Prepare Authorization Lookup

Usar un Code node antes de `Check Authorization`:

```javascript
const update = $json;
const message = update.message ?? update.edited_message ?? update.callback_query?.message ?? {};
const from = update.message?.from ?? update.callback_query?.from ?? message.from ?? {};
const contact = update.message?.contact ?? null;

const telegramUserId = from?.id ? Number(from.id) : null;
const contactUserId = contact?.user_id ? Number(contact.user_id) : null;
const contactBelongsToSender =
  Boolean(contact?.phone_number) &&
  telegramUserId !== null &&
  contactUserId !== null &&
  telegramUserId === contactUserId;

return [
  {
    json: {
      telegram_user_id: telegramUserId,
      telegram_phone_number: contactBelongsToSender ? contact.phone_number : null,
      contact_required: !contactBelongsToSender,
      username: from?.username ?? null,
      first_name: from?.first_name ?? null,
      last_name: from?.last_name ?? null,
    },
  },
];
```

## Nodo Check Authorization

Opcion recomendada: usar HTTP Request contra Supabase RPC con service role key.

Config:

- Method: `POST`
- URL: `https://<PROJECT_REF>.supabase.co/rest/v1/rpc/is_admin_telegram_user_authorized`
- Headers:
  - `apikey: {{ $env.SUPABASE_SERVICE_ROLE_KEY }}`
  - `Authorization: Bearer {{ $env.SUPABASE_SERVICE_ROLE_KEY }}`
  - `Content-Type: application/json`
- Body:

```json
{
  "p_telegram_user_id": "={{ $json.telegram_user_id }}",
  "p_telegram_phone_number": "={{ $json.telegram_phone_number }}"
}
```

Respuesta esperada:

```json
[
  {
    "authorized": true,
    "id": 1,
    "telegram_user_id": 123456789,
    "telegram_phone_number": "+5491112345678",
    "username": "usuario_admin",
    "first_name": "Nombre",
    "last_name": "Apellido"
  }
]
```

## Vincular el user id de Telegram

Despues de autorizar por telefono compartido, se puede llamar este RPC para guardar el `telegram_user_id` y permitir autorizaciones futuras por id:

- Method: `POST`
- URL: `https://<PROJECT_REF>.supabase.co/rest/v1/rpc/link_admin_telegram_user_identity`
- Headers:
  - `apikey: {{ $env.SUPABASE_SERVICE_ROLE_KEY }}`
  - `Authorization: Bearer {{ $env.SUPABASE_SERVICE_ROLE_KEY }}`
  - `Content-Type: application/json`
- Body:

```json
{
  "p_telegram_user_id": "={{ $json.telegram_user_id }}",
  "p_telegram_phone_number": "={{ $json.telegram_phone_number }}",
  "p_username": "={{ $json.username }}",
  "p_first_name": "={{ $json.first_name }}",
  "p_last_name": "={{ $json.last_name }}"
}
```

## Ruteo n8n recomendado

1. Telegram Trigger
2. Prepare Authorization Lookup
3. Check Authorization
4. IF `authorized === true`
5. Si no esta autorizado y no compartio contacto, pedir contacto con un keyboard de Telegram.
6. Si compartio contacto pero no esta en la tabla, responder acceso denegado.
7. Si esta autorizado, continuar con las acciones del bot.

## Seguridad

- Usar `SUPABASE_SERVICE_ROLE_KEY` solo dentro de n8n, nunca en frontend.
- No usar la anon key para consultar esta tabla.
- Mantener RLS activo.
- Desactivar usuarios cambiando `is_active = false`, no borrandolos, para conservar auditoria basica.
